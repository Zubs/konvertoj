# konvertoj — Features

This document breaks down every v1 feature from [Spec.md](Spec.md), in the order they should be built. Each feature builds on the ones before it. The command-line foundation comes first, so every conversion after it gets help text, output naming, batch processing and error handling for free.

Tick a feature in the list below when everything under **How it works** is built and all its **Tests** pass.

Decisions taken outside this plan are listed, with their reasons, in [Decisions.md](Decisions.md).

Tests are listed in **ZOMBIES** order: **Z**ero (nothing given or empty input), **O**ne (a single item), **M**any (several items), **B**oundaries (limits and edge values), **I**nterfaces (how it connects to the command line and other features), **E**xceptions (errors and bad input), then a **S**imple real-world scenario last.

## Foundation

### 1. Project setup

**What it does:** Creates the TypeScript project, the test suite and continuous testing on all three operating systems, so every later feature is checked on Windows, macOS and Linux from day one.

**How it works**
- A TypeScript project on Node.js 22 or newer, written as ES modules.
- `tsc` compiles `src/` into `dist/`, file for file, with `"module": "NodeNext"`. Imports between source files end in `.js`, as Node.js requires for ES modules. `src/cli.ts` starts with a `#!/usr/bin/env node` line, which `tsc` keeps.
- `package.json` sets the name `konvertoj`, `"bin": { "konvertoj": "dist/cli.js" }`, `"engines": { "node": ">=22" }` and a `files` list so only `dist/`, `README.md` and `LICENSE` are published.
- Vitest runs the tests. Test images are generated by the tests themselves where possible. A small `test/fixtures/` folder holds only the files that can't be generated, such as a real iPhone HEIC photo, a short MOV clip and a two-page PDF.
- ESLint and Prettier keep the code consistent. The scripts are `npm run format` (Prettier), `npm run check` (type checks and ESLint), `npm test` (Vitest) and `npm run build` (`tsc`).
- GitHub Actions runs `npm run check`, `npm test` and `npm run build` on Ubuntu, macOS and Windows for every push and pull request.
- MIT licence.

**Tests**
- With an empty `src/` entry point, the project builds and `node dist/cli.js` exits without errors.
- One sample test passes locally and in CI.
- The CI workflow runs on all three operating systems, and a failure on any one fails the run.
- `npm pack --dry-run` lists only `dist/`, `README.md`, `LICENSE` and `package.json`, with no tests or fixtures.
- The built `dist/cli.js` starts with the `#!/usr/bin/env node` line.
- Running with Node.js older than 22 prints a clear "konvertoj needs Node.js 22 or newer" message instead of a crash.
- A developer clones the repository, runs `npm install`, `npm run check`, `npm test` and `npm run build`, and everything passes.

**Done when:** The project builds, the tests run, and CI passes on Windows, macOS and Linux.

### 2. Command-line basics

**What it does:** The shape of every command: `-m/--mode`, the help screen, `--version`, `--list-modes`, per-mode help and "Did you mean…?" suggestions.

**How it works**
- Node's built-in `util.parseArgs` reads the arguments. Every common option and every mode option is declared, then options that don't belong to the chosen mode are rejected (see below).
- A **mode registry** is the single source of truth. Each mode is defined once with its name, group (Image, PDF, GIF, Video & Audio, Tools), accepted input formats, output format, options, a one-line description and examples. The help screens, `--list-modes`, input checks and the README examples all read from it, so they can't drift apart.
- Conversion modes are generated from the format lists as `<from>to<to>` (e.g. `heictojpg`), plus `to<format>` (e.g. `tojpg`). There is one spelling per mode, all lowercase, and `jpg` and `tiff` are the canonical names.
- Running `konvertoj` with no arguments shows the help screen: what the tool does, the command shape, a few common examples and a pointer to `--list-modes`.
- `konvertoj -m <mode> --help` shows that mode's description, options with defaults and examples.
- An unknown mode suggests the closest real mode, using edit distance, and also matches common variants: `heic2jpg`, `heic-to-jpg` and `HEICtoJPG` all suggest `heictojpg`.
- Common options are registered once and shared by every mode: `-o/--output`, `--overwrite`, `--strip-metadata`, `-r/--recursive`, `--dry-run`, `-q/--quiet`, `-v/--verbose`.
- Options that don't belong to the chosen mode are rejected, e.g. `--angle` with `heictojpg`.

**Tests**
- Running `konvertoj` with no arguments shows the help screen and exits successfully.
- `--version` prints the version from `package.json`.
- `--list-modes` lists every mode once, grouped under Image, PDF, GIF, Video & Audio and Tools.
- `-m heictojpg --help` shows that mode's description, options and at least one example.
- `-m` and `--mode` behave identically, and so do `-o` and `--output`.
- Every mode in the registry has a description, at least one example and a group.
- `heic2jpg`, `heic-to-jpg`, `HEICtoJPG` and `heictojgp` each fail with "Did you mean heictojpg?".
- A mode name with no close match fails and points to `--list-modes`.
- `-m` with no value, or a file with no `-m`, fails with a clear message showing the command shape.
- An option from another mode (e.g. `--angle` with `heictojpg`) fails, naming the option and the mode.
- A first-time user types `npx konvertoj`, reads the help, runs `--list-modes`, then checks one mode's help.

**Done when:** The help screens, `--list-modes` and suggestions all come from the mode registry, and every wrong command gets a helpful message.

### 3. Inputs and output naming

**What it does:** Turns what the user typed into a list of input files and a matching list of safe output paths.

**How it works**
- Inputs can be one or more files, folders or patterns. Patterns use `fast-glob`, so they work the same on Windows, where the shell doesn't expand `*`.
- Folders include only their top level, or every subfolder with `-r/--recursive`. Hidden files and folders are skipped.
- Inputs are sorted in natural order (`page2` before `page10`) and duplicates are removed.
- Output naming rules:
  - `-o newimage` → `newimage.jpg`, with the extension added from the mode.
  - `-o newimage.jpg` → used as given.
  - `-o newimage.png` with a JPG mode → a warning, then `newimage.jpg`. The mode wins.
  - No `-o` on a conversion → the input's name with the new extension, in the input's folder.
  - No `-o` on a tool mode that keeps the format (e.g. `compress`) → a suffix named after the tool, e.g. `hero-compressed.jpg`, so the original is never touched.
  - Several inputs with `-o` → `-o` is a folder, created if missing. With `--recursive`, the subfolder structure is kept inside it.
- If the output already exists, a number is added (`photo (1).jpg`, `photo (2).jpg`) unless `--overwrite` is given. Even with `--overwrite`, an input file is never replaced by its own output.
- Two inputs in one run that would produce the same output name (e.g. `photo.png` and `photo.jpg` → `photo.webp`) are numbered too.
- Results are written to a temporary file first and renamed when complete, so a failure never leaves a half-written file.
- `--dry-run` prints each planned input → output pair and writes nothing.

**Tests**
- No input files fails with "No input files given", and an empty folder or a pattern that matches nothing fails with "No matching files found".
- One file with no `-o` produces the input's name with the new extension, in the same folder.
- One file with `-o newimage` produces `newimage.jpg`, and `-o newimage.jpg` doesn't become `newimage.jpg.jpg`.
- `-o newimage.png` with a JPG mode warns and produces `newimage.jpg`.
- Three files with `-o converted` create the `converted` folder and three outputs inside it.
- A folder without `--recursive` ignores subfolders, and with `--recursive` keeps the subfolder structure in the output.
- `page1`, `page2` and `page10` are processed in that order.
- The same file given twice is processed once.
- Hidden files such as `.DS_Store` are skipped.
- An existing `photo.jpg` makes the new output `photo (1).jpg`, and an existing `photo (1).jpg` makes it `photo (2).jpg`.
- `--overwrite` replaces an existing output, but never the input file itself.
- Two inputs that would produce the same name get separate, numbered outputs.
- File names with spaces, accents, emoji and very long names work on all three operating systems.
- Quoted patterns like `"photos/*.heic"` work on Windows.
- `--dry-run` lists every input → output pair and creates no files or folders.
- A file that doesn't exist fails with its name in the message, and a file that can't be read fails with a permissions message.
- An output folder that can't be written to fails before any work starts.
- If a conversion fails part-way, no partial output file is left behind.
- A user converts a folder of photos into a new folder, runs it again and gets numbered copies instead of lost files.

**Done when:** Every combination of inputs and `-o` produces predictable output names, and no command can overwrite an original.

### 4. Batch runner and reporting

**What it does:** Runs a mode over every input, shows progress, reports a summary and exits with a code that scripts can rely on.

**How it works**
- Files are processed a few at a time, with the number set by CPU cores (at most 4), to keep memory use safe.
- One failed file doesn't stop the rest. Its error is collected and shown in the summary.
- A one-line progress bar, redrawn in place with `\r`, shows `Converting 37/120…` when the output is a terminal. Long single jobs, such as video, can report their own percentage and time left.
- The end summary shows succeeded, failed and skipped counts, total size before → after, and time taken.
- Exit codes: `0` everything succeeded, `1` nothing succeeded or the command was invalid, `2` some files failed.
- `-q/--quiet` shows only errors. `-v/--verbose` adds the detail of each step and full error details.
- Colours use Node's built-in `util.styleText`. Colours and the progress bar turn off automatically when the output isn't a terminal or `NO_COLOR` is set.
- Every error shown to the user is a plain-English message with a suggested fix. Technical errors only appear with `--verbose`.
- Ctrl+C stops cleanly, removes any half-written files and prints what was finished.
- Until real modes exist, a test-only `copy` mode is used to test the runner. It's never published.

**Tests**
- With no inputs, the runner does nothing and reports nothing, because feature 3 has already stopped the command.
- One successful file prints one success line and a summary, and exits with `0`.
- Ten files all succeeding exit with `0`, and the summary shows 10 succeeded.
- Ten files where three fail process all ten, list the three failures with reasons and exit with `2`.
- Ten files that all fail exit with `1`.
- The before → after sizes in the summary add up correctly, including when an output is bigger than its input.
- No more than 4 files are processed at once, even on a machine with many cores.
- `--quiet` prints nothing on success and only the errors on failure.
- `--verbose` shows the full technical error for a failure.
- When the output is piped to a file, it has no colour codes or progress bar.
- `NO_COLOR=1` turns colours off.
- An unexpected error inside a mode is reported as a friendly message, not a stack trace, unless `--verbose` is on.
- Pressing Ctrl+C mid-batch stops, removes half-written files and keeps the finished ones.
- A script converts a folder and checks the exit code to decide whether to continue.

**Done when:** Batches keep going past failures, the summary is accurate, and the exit codes are `0`, `1` and `2` as described.

### 5. Format detection

**What it does:** Works out each file's real format from its contents, so `to<format>` modes work and wrong-mode mistakes get a helpful message.

**How it works**
- `file-type` reads the first bytes of each file to identify its format. The file extension is only used as a fallback, e.g. for SVG, which is text.
- `.jpg`, `.jpeg`, `.jfif` and `.jpe` are all JPG. `.tif` and `.tiff` are both TIFF. `.heic` and `.heif` are both HEIC.
- A `<from>to<to>` mode checks each input matches `<from>`. If it doesn't, the file fails with a suggestion, e.g. *"holiday.heic looks like a PNG. Try: -m pngtojpg"*.
- A `to<format>` mode accepts any supported input and picks the right converter for each file, so one batch can mix formats.
- A file that already matches the target in a `to<format>` mode (e.g. a JPG with `tojpg`) is skipped with a note, unless a conversion option such as `--quality` is given.

**Tests**
- An empty (0-byte) file fails with "is empty".
- A real HEIC with a `.heic` extension is detected as HEIC.
- A PNG renamed to `.heic` is detected as PNG, fails `heictojpg` with a "Try: -m pngtojpg" suggestion, and converts fine with `tojpg`.
- A mixed folder of HEIC, PNG and WebP files all convert with `tojpg`.
- `.jpeg`, `.jfif` and `.JPG` files are all accepted by `jpgtopng`.
- An SVG with no extension is detected from its contents.
- A JPG with `tojpg` and no options is skipped and counted as skipped, and with `--quality 60` is converted.
- A text file renamed to `.jpg` fails with "isn't a file konvertoj can convert".
- A supported but wrong kind of file (e.g. an MP4 given to `topdf`) fails, naming the modes that do accept it.
- A truncated or corrupt image fails with "looks damaged" instead of a crash.
- A user runs `tojpg` on a messy downloads folder and gets JPGs for everything convertible and a clear list of what was skipped.

**Done when:** Files are recognised by their contents, `to<format>` works on mixed batches, and a wrong mode always suggests the right one.

## Images

### 6. Core image conversion

**What it does:** Converts between JPG, PNG, WebP, AVIF, GIF and TIFF with the common options.

**How it works**
- `sharp` (libvips) does the work. Its prebuilt binaries install automatically on Windows, macOS and Linux, so no extra software is needed.
- Options: `--quality 1–100` (default per format, e.g. 80 for JPG), `--background <colour>` when transparency is lost (default white), `--lossless` for WebP and AVIF, `--progressive` for JPG, `--grayscale`. Feature 9 adds `--width`, `--height` and `--fit`.
- Colours are accepted as names (`white`), hex (`#ff8800`) or `rgb(…)`.
- Animated GIFs and WebPs stay animated when the target supports animation (GIF, WebP). For other targets the first frame is used, with a note.
- Images are turned upright using their orientation tag, so phone photos never come out sideways.
- Colour profiles are converted to sRGB so colours look the same everywhere.

**Tests**
- A 1×1 pixel image converts in every direction.
- One PNG converts to JPG, WebP, AVIF, GIF and TIFF, and each output opens as the right format with the same dimensions.
- All 30 pairs among the six formats work.
- `--quality 1` and `--quality 100` work, and `0`, `101` and `abc` are rejected.
- A transparent PNG converted to JPG has a white background by default, and a red one with `--background red`.
- `--background #ff8800` and `--background rgb(255,136,0)` give the same colour, and an invalid colour is rejected.
- A lower `--quality` gives a smaller file than a higher one for the same image.
- `--lossless` WebP keeps every pixel identical to the source.
- An animated GIF to WebP stays animated with the same frame count, and to JPG uses the first frame with a note.
- A phone photo with an orientation tag comes out upright.
- A very large image (e.g. 20,000 × 20,000 pixels) converts or fails with a clear "too large" message, never a crash.
- `--lossless` with a JPG mode is rejected, because JPG can't be lossless.
- A user converts a folder of PNG screenshots to WebP at quality 80 and sees the space saved in the summary.

**Done when:** Every pair of the six core formats converts correctly, with quality, background and animation handled as described.

### 7. Other image formats

**What it does:** Adds the remaining image formats: HEIC (iPhone photos) and SVG as inputs, and BMP and ICO (favicons) as both inputs and outputs.

**How it works**
- **HEIC:** `sharp`'s prebuilt binaries can't read HEIC, so `heic-decode` (libheif compiled to WebAssembly) decodes it into raw pixels, which are then passed to `sharp`. Nothing extra needs installing.
  - For files with several images (bursts, Live Photos), the main image is used.
  - Camera details are read with `exifr` and carried over in feature 8.
  - HEIC is input only. Creating HEIC files needs patent-licensed HEVC encoding, which no install-free library includes.
- **BMP:** read and written with `bmp-ts`, then passed to and from `sharp` as raw pixels.
- **ICO:** read with `decode-ico` and written by konvertoj's own small ICO writer, which packs PNG images into the ICO container.
  - `--sizes 16,32,48` sets which sizes go into an ICO (default `16,32,48`). Each size is resized from the source and kept square.
  - Reading an ICO uses its largest image.
- **SVG:** rendered by `sharp`.
  - `--width`, `--height` or `--dpi` set the output size, because an SVG has no fixed pixel size. The default is the SVG's own size, or 512 pixels wide if it has none.
  - Transparency is kept for PNG, WebP, AVIF and GIF output.
  - External files and links inside the SVG are not loaded, for safety.
  - SVG is input only (see Spec, out of scope).

**Tests**
- A 0-byte `.heic` file fails with "is empty" (feature 5).
- An SVG with no content produces a blank image of the default size.
- A real iPhone HEIC converts to JPG with the right dimensions and is upright.
- A 1×1 BMP converts to PNG and back.
- One PNG converts to an ICO containing 16, 32 and 48 pixel images by default.
- One SVG converts to PNG at its own size.
- A HEIC converts to every core format.
- A folder of 20 HEIC photos converts without running out of memory.
- `--sizes 16,32,64,128,256` produces an ICO with all five sizes.
- An ICO with several sizes converts to PNG using the largest.
- A portrait iPhone photo stays portrait.
- A HEIC with several images converts its main image only.
- `--sizes 256` works, and `0`, `257` and `abc` are rejected.
- A non-square image becomes square in the ICO without stretching, with transparent padding.
- An SVG without a width or height produces a 512-pixel-wide output.
- `--width 2000` on an SVG produces a sharp 2000-pixel-wide PNG, not a blurry enlargement.
- The ICO output opens correctly in a browser as a favicon and in Windows.
- BMP and ICO appear in `--list-modes`, and `tobmp` and `toico` work on any input.
- A transparent SVG stays transparent as PNG and gets a white background as JPG.
- An SVG that links to an external image renders without loading it.
- `pngtoheic`, `toheic`, `pngtosvg` and `tosvg` don't exist, and asking for them explains that HEIC and SVG are input only.
- A damaged HEIC, BMP, ICO or SVG fails with "looks damaged".
- A user converts their whole iPhone export folder with `heictojpg ./iphone -o ./jpgs`, and a developer turns their logo SVG into PNGs and a `favicon.ico`.

**Done when:** HEIC and SVG files convert to every output format, BMP and ICO convert both ways, and ICO files contain the requested sizes, all with no extra installs.

### 8. Metadata and strip

**What it does:** Keeps camera and location details by default, removes them with `--strip-metadata`, and adds the `strip` tool.

**How it works**
- By default, EXIF, ICC and XMP metadata is copied to the output wherever the format supports it (JPG, PNG, WebP, AVIF, TIFF), using `sharp`'s `keepMetadata()`.
- For HEIC input, the main EXIF fields (camera, date, GPS, orientation) are read with `exifr` and written with `sharp`'s `withExif()`.
- `--strip-metadata` works on every image mode and removes everything except the colour profile. The image is turned upright first, so removing the orientation tag never leaves it sideways.
- `strip` is a tool mode that keeps the format and only removes metadata. Its default output name is `<name>-stripped.<ext>`.

**Tests**
- An image with no metadata converts without errors and gains none.
- A JPG with camera, date and GPS details keeps all three after `jpgtowebp`.
- A HEIC's camera, date and GPS details appear in the JPG after `heictojpg`.
- `--strip-metadata` removes camera, date and GPS details from the output.
- `strip` on a JPG removes the details, keeps the pixels and keeps the format.
- `strip` on a sideways photo produces an upright image with no orientation tag.
- Converting to a format without metadata support (BMP, GIF, ICO) works and notes that details were dropped (`--verbose`).
- `--strip-metadata` works with every image mode, including `resize` and `compress` later.
- A file with damaged metadata still converts, with the metadata skipped and a warning.
- A user strips location details from a folder of photos before posting them online.

**Done when:** Details are kept by default, removed completely with `--strip-metadata` or `strip`, and images are never left sideways.

### 9. Resize and enlarge

**What it does:** Changes an image's dimensions with `resize`, upscales it with `enlarge`, and adds `--width`, `--height` and `--fit` to every conversion mode.

**How it works**
- **Resize:** `--width`, `--height`, `--scale 50%`, `--fit contain|cover|fill|inside|outside` (default `inside`) and `--no-enlarge`.
  - Giving only one of width or height keeps the shape.
  - The same resize step is shared with conversion modes, so `heictojpg --width 1200` works.
- **Enlarge:** `--scale 2x|4x` (default `2x`), using the same resize step with the high-quality Lanczos method, then a light sharpen to reduce softness.
- Results larger than 16,384 pixels on a side are refused with a clear message.
- Default output names: `<name>-resized.<ext>` and `<name>-enlarged.<ext>`.

**Tests**
- `resize` with no size option fails with "Give --width, --height or --scale".
- `enlarge` with no options doubles the size.
- `--width 800` on a 1600 × 1200 image gives 800 × 600.
- `enlarge --scale 4x` turns 400 × 300 into 1600 × 1200.
- Each `--fit` value gives the expected dimensions for a wide and a tall image, and `--width 800 --height 800 --fit cover` gives exactly 800 × 800, cropped from the centre.
- `--scale 50%` halves both dimensions, and `--scale 200%` doubles them.
- A folder of small icons all enlarge.
- `--width 1` works, and `0`, negative and non-numeric sizes are rejected.
- `--no-enlarge` on a 400-pixel image with `--width 800` leaves it at 400 pixels, with a note.
- An odd result such as 333.5 pixels is rounded, never fails.
- A 1 × 1 image enlarges to 2 × 2.
- A result that would exceed 16,384 pixels on a side is refused with its would-be size.
- `enlarge --scale 3x`, `--scale 1x` and `--scale abc` are rejected, listing `2x` and `4x`.
- `heictojpg --width 1200` resizes while converting.
- Resizing an animated GIF keeps it animated.
- A transparent PNG stays transparent after resizing or enlarging.
- `--strip-metadata` works with both `resize` and `enlarge`.
- `--scale` together with `--width` is rejected as conflicting.
- A writer resizes a folder of screenshots to 1200 pixels wide for a blog post, and enlarges an old small photo to 4x for printing.

**Done when:** Resizing works on its own and inside every conversion, every `--fit` option behaves as described, images enlarge to exactly 2x or 4x, and oversized results are refused clearly.

### 10. Compress

**What it does:** Makes images smaller while keeping them looking good.

**How it works**
- Options: `--quality 1–100`, `--level low|medium|high` (quality 85, 70 and 50) or `--target-size 200kb`. With none given, `medium` is used.
- JPG, WebP and AVIF are re-encoded at the chosen quality. PNG uses palette quantisation, and GIF uses fewer colours.
- `--target-size` tries qualities with a binary search (at most 8 attempts) and keeps the highest quality under the target. If the target can't be reached, the smallest result is kept, with a warning.
- If the result isn't smaller than the original, nothing is written. The file is reported as "already optimised" and counted as skipped.
- Each file shows before → after sizes, e.g. `hero.jpg 2.4 MB → 410 KB (−83%)`.
- Default output name: `<name>-compressed.<ext>`.

**Tests**
- Compressing with no options uses the `medium` level.
- One large JPG ends up smaller, at the same dimensions, with a before → after line.
- A folder of mixed JPG, PNG and WebP files all compress, and the summary total matches the per-file lines.
- `--level high` gives a smaller file than `--level low`.
- `--target-size 200kb` gives a file at or under 200 KB, at the highest quality that fits.
- `--target-size` accepts `kb` and `mb` in any case, and rejects `0`, negatives and `200` with no unit.
- An unreachable target (e.g. `1kb` for a large photo) keeps the smallest result and warns.
- An image that doesn't get smaller is reported as "already optimised", no file is written, and it counts as skipped in the summary.
- A transparent PNG stays transparent after compression.
- `--quality` with `--level` or `--target-size` is rejected as conflicting.
- `compress` on a format it can't compress (BMP, ICO) explains which formats are supported.
- A developer compresses a website's images folder before committing and sees the total saved.

**Done when:** Files get smaller, `--target-size` hits its target when possible, and a file that can't be made smaller is skipped instead of written.

### 11. Crop, rotate and flip

**What it does:** Cuts images to an area, a position or an aspect ratio, trims plain borders, and turns or mirrors images.

**How it works**
- **Crop:**
  - Exact area: `--width`, `--height`, `--left`, `--top`.
  - Position: `--width`, `--height` and `--position center|top|bottom|left|right|top-left|top-right|bottom-left|bottom-right` (default `center`).
  - Aspect ratio: `--aspect 16:9` crops the largest area with that ratio, at `--position`.
  - Trim: `--trim` removes borders that match the corner colour.
- **Rotate:** `--angle <degrees>` works with any angle, positive or negative. Angles that aren't multiples of 90 enlarge the canvas and fill the corners with `--background` (transparent where supported, otherwise white). `--auto` turns the image upright using its orientation tag and then clears the tag.
- **Flip:** `--direction horizontal|vertical`.
- Default output names: `<name>-cropped.<ext>`, `<name>-rotated.<ext>` and `<name>-flipped.<ext>`.

**Tests**
- `crop` with no options fails with a list of the ways to crop.
- `rotate` with neither `--angle` nor `--auto` fails with a usage hint.
- `crop --width 800 --height 800` on a 1600 × 1200 image gives a centred 800 × 800 crop.
- `--angle 90` turns an 800 × 600 image into 600 × 800.
- `flip --direction horizontal` mirrors left to right, and `vertical` top to bottom.
- Each `--position` value takes the crop from the right place.
- `--aspect 1:1` on a 1600 × 1200 image gives 1200 × 1200, and `--aspect 16:9` gives 1600 × 900.
- `--angle 90`, `180`, `270` and `-90` all give the expected results.
- A crop exactly the size of the image returns the same image.
- A crop that goes past the edge of the image fails, showing the image's real size.
- `--angle 0` and `--angle 360` leave the image unchanged.
- `--angle 45` enlarges the canvas, with transparent corners for PNG and white corners for JPG.
- `--trim` removes a plain white border from a screenshot, and on an image with no border leaves it unchanged, with a note.
- `--auto` on a sideways phone photo makes it upright, and on an already-upright photo changes nothing.
- Rotating or flipping an animated GIF keeps it animated.
- `--aspect 0:9`, `--aspect 16`, `--aspect abc` and `--angle abc` are rejected.
- `--left` without `--top`, or `--aspect` with `--trim`, is rejected as incomplete or conflicting.
- `flip` with no direction or an unknown one fails, listing `horizontal` and `vertical`.
- A creator crops a folder of photos to 1:1 for a social media post, and fixes a folder of pages that were all scanned upside down.

**Done when:** Every crop method gives the exact expected result, impossible crops fail with the image's real size, rotating by any angle and flipping in both directions are correct, and `--auto` fixes sideways photos.

### 12. Info and colour picker

**What it does:** Two tools that read an image without changing it: `info` shows its details, and `colorpick` reports its colours.

**How it works**
- **Info:** shows the format, file size, dimensions, colour space, whether it has transparency, frame count for animations, and a metadata summary (camera, date taken, whether GPS location is present). GPS coordinates are only shown with `--verbose`, so they aren't printed by accident.
- **Colour picker:**
  - `--at x,y` reports the pixel at that point, counted from the top left starting at 0.
  - `--palette <n>` reports the image's `n` main colours (default 5, maximum 16) using median-cut quantisation, from most to least common.
  - Each colour is shown as HEX, RGB and HSL, with a coloured block in the terminal. Transparency is included when the colour isn't fully opaque.
- Both print one section per file, `--json` prints the same as JSON for scripts, and neither writes a file, so `-o` isn't allowed.

**Tests**
- `info` with no file fails (feature 3), and `colorpick` with neither `--at` nor `--palette` fails with a usage hint.
- One JPG's `info` shows its format, size, dimensions and camera details.
- `--at 0,0` on an image whose top-left pixel is pure red reports `#FF0000`, `rgb(255, 0, 0)` and `hsl(0, 100%, 50%)`.
- Several input files print one section each, for both tools.
- `--palette 3` on an image made of red, green and blue stripes reports those three colours.
- A 1 × 1 image and a very large image both show the right dimensions.
- `--at` on the last pixel works, and one pixel past the edge fails, showing the image's size.
- `--palette 1` and `--palette 16` work, and `0`, `17` and `abc` are rejected.
- An animated GIF shows its frame count.
- A photo with GPS shows "Location: yes" without coordinates, and shows the coordinates only with `--verbose`.
- An image with no metadata shows "No camera details" instead of empty fields.
- A half-transparent pixel reports its transparency.
- `--json` prints valid JSON containing every field, for both tools.
- Both tools work on every supported image input format, including HEIC, SVG, BMP and ICO.
- `-o` with either tool is rejected, explaining it doesn't create files.
- A user checks whether a photo still holds location details before sharing it, and a designer pulls the five main colours from a brand photo.

**Done when:** `info` shows accurate details for every supported image format and never prints a location by accident, colours are reported correctly in HEX, RGB and HSL, and `--json` works for scripts.

## PDF

### 13. PDF

**What it does:** Turns one or many images into a single PDF, and exports PDF pages as images.

**How it works**
- **Images to PDF:**
  - `pdf-lib` builds the PDF. JPGs are embedded as they are, PNGs keep their transparency, and every other format is converted to PNG or JPG with `sharp` first.
  - Modes: `jpgtopdf`, `pngtopdf`, `heictopdf` and the other per-format modes, plus `topdf`, which accepts any image.
  - Pages follow the input order (natural sort for folders and patterns).
  - Options: `--page-size A4|letter|fit` (default `A4`; `fit` makes each page match its image), `--orientation portrait|landscape|auto` (default `auto`), `--margin` in millimetres (default `0` for `fit`, `10` for A4 and letter).
  - On A4 and letter pages, images are scaled down to fit inside the margins and centred, never stretched.
  - All inputs produce one PDF. `-o` names it, and without `-o` it is named after the first input.
- **PDF to images:**
  - `pdfjs-dist` (Mozilla's PDF engine) reads the PDF, and `@napi-rs/canvas` (prebuilt, no extra installs) draws each page.
  - Modes: `pdftojpg`, `pdftopng`, `pdftowebp` and the other image formats.
  - `--page 3`, `--page 1-5`, `--page 1,3,7` or `--page all` (default `all`).
  - `--dpi` sets sharpness (default 150, range 36–600).
  - Outputs are named `<name>-1.png`, `<name>-2.png` and so on, padded to sort properly (`-01` to `-12` for a 12-page PDF). `-o` is a folder.

**Tests**
- No images fails (feature 3), and a PDF with no pages fails with "has no pages".
- One JPG makes a one-page A4 PDF with the image centred inside a 10 mm margin.
- A one-page PDF produces one image.
- Three images make a three-page PDF in the given order, and `page1`, `page2` and `page10` end up in that order.
- A two-page PDF produces two images, numbered in order.
- A large image is scaled down to fit the A4 page and a small one is centred, and neither is stretched.
- `--page-size fit` makes each page match its image, with no margin, and `--page-size letter` makes every page US letter.
- `--orientation auto` makes a wide image's page landscape and a tall image's page portrait.
- `--margin 0` and `--margin 50` work, and a margin bigger than half the page is rejected.
- `--page 2` exports only page 2, and `--page 1-2` exports both.
- `--page 3` on a two-page PDF fails, saying the PDF has 2 pages, and `--page 0`, `--page 2-1` and `--page abc` are rejected.
- `--dpi 300` produces images twice the size of `--dpi 150`, and `35` and `601` are rejected.
- A 12-page PDF names its pages `-01` to `-12`.
- A transparent PNG keeps its transparency in the PDF.
- HEIC, WebP and AVIF images can all be included in a PDF.
- Mixing formats works with `topdf` and is rejected by `jpgtopdf` with a `topdf` suggestion.
- The PDF opens correctly in common PDF readers.
- Text, images and vector drawings on a PDF page all appear in the exported image.
- A damaged image in the list stops the PDF and names the file, rather than leaving a page out silently.
- A password-protected PDF fails with "is password-protected", and a damaged PDF fails with "looks damaged".
- A user scans receipts with their phone and turns the HEIC photos into one A4 PDF, then exports page 3 of a report as a PNG for a slide.

**Done when:** Any set of images becomes one PDF in the right order with the chosen page size, and any page or range of a PDF exports as images at the chosen sharpness.

## Video and audio

### 14. FFmpeg add-on

**What it does:** Finds FFmpeg or offers a one-time download, so video and audio modes work with no setup beyond saying yes.

**How it works**
- When a video or audio mode runs, konvertoj looks for FFmpeg in this order:
  1. `KONVERTOJ_FFMPEG_PATH` if it's set
  2. FFmpeg already installed on the computer (in `PATH`), if it's version 5 or newer
  3. A copy konvertoj downloaded before, saved in the user's cache folder: `%LOCALAPPDATA%\konvertoj` on Windows, `~/Library/Caches/konvertoj` on macOS, and `$XDG_CACHE_HOME/konvertoj` or `~/.cache/konvertoj` on Linux
- If none is found, konvertoj asks: *"Video and audio need a one-time download of <size> MB. Continue? (Y/n)"*, showing the exact size of the download for that computer
- The download comes from pinned release URLs for each operating system and processor, the same static builds `ffmpeg-static` uses. These builds are GPL-licensed. Because they're downloaded separately at the user's request, konvertoj itself stays MIT-licensed. The download is checked against a SHA-256 checksum stored in konvertoj before use, and kept for every later run, including through `npx`.
- `konvertoj --install-video` downloads the add-on in advance, after the same prompt.
- Non-interactive runs (scripts, CI) never prompt or download. They fail with instructions to run `konvertoj --install-video` first, or to install FFmpeg.
- If the user is offline or declines, konvertoj explains both routes: run `--install-video` later, or install FFmpeg themselves. Image and PDF modes are never affected.
- konvertoj runs FFmpeg as a separate process with arguments passed safely (never through a shell), and reads its progress output to show percentage and time left.

**Tests**
- With no FFmpeg found and the prompt declined, the mode fails with both routes explained and exits with `1`.
- With FFmpeg installed on the computer, nothing is downloaded and it's used.
- With FFmpeg 4 installed, it's ignored and the download is offered instead.
- With `KONVERTOJ_FFMPEG_PATH` set, that copy is used even if another is installed.
- Accepting the prompt downloads, verifies and saves the add-on, and the conversion continues.
- A second run uses the saved copy without prompting or downloading.
- The add-on is saved in the right cache folder on Windows, macOS and Linux, and `XDG_CACHE_HOME` is used on Linux when it's set.
- Two runs at the same time don't both download or corrupt the saved copy.
- A download with a wrong checksum is deleted and fails clearly.
- A download that fails part-way leaves nothing behind, and the next run offers it again.
- The prompt shows the exact download size for the computer's operating system and processor.
- In a non-interactive run, the mode fails without downloading and tells the user to run `--install-video` first.
- `--install-video` downloads the add-on in advance, and running it again when the add-on is already there says so and downloads nothing.
- Offline, the failure says no connection was available and image modes still work.
- A file name with spaces or quotes is passed to FFmpeg safely.
- A first-time user runs `npx konvertoj -m movtomp4 clip.mov`, accepts the download and gets an MP4.

**Done when:** Video modes work with an installed FFmpeg straight away, and without one after a single confirmed download.

### 15. Video to MP4

**What it does:** Converts MOV and other common video files to MP4 that plays everywhere.

**How it works**
- Modes: `movtomp4`, `mkvtomp4`, `avitomp4`, `webmtomp4`, `m4vtomp4` and `tomp4`.
- Video is encoded as H.264 and audio as AAC. iPhone HEVC video is re-encoded for compatibility. `+faststart` is set so the video starts playing before it has fully downloaded.
- `--quality low|medium|high` (CRF 28, 23 and 18, default `medium`), `--resolution 1080p|720p|480p` (only ever scales down, keeping the shape), `--mute` drops the audio.
- Video rotation (e.g. phone videos filmed upright) is kept.
- Progress shows a percentage and time left.

**Tests**
- A video with no frames, or a 0-byte file, fails with "has no video".
- One iPhone MOV converts to an MP4 that plays in browsers and on Windows, macOS, Android and iOS.
- A folder of MOV files converts one at a time, with an overall count and per-file progress.
- `--resolution 720p` on a 4K video gives 1280 × 720, and on a 480p video leaves it unchanged with a note.
- `--quality high` gives a bigger file than `--quality low`.
- A one-second clip and a long video (over an hour) both convert.
- A video filmed upright on a phone stays upright.
- A video with no audio converts without errors.
- `--mute` produces an MP4 with no audio track.
- MKV, AVI, WebM and M4V inputs all convert with `tomp4`.
- `--resolution 4k` and `--quality max` are rejected, listing the allowed values.
- A damaged video fails with "looks damaged", and Ctrl+C removes the half-written MP4.
- A user converts the iPhone videos from a holiday into MP4s to share with family.

**Done when:** Every supported video format becomes an MP4 that plays everywhere, keeping its rotation.

### 16. Audio from video

**What it does:** Extracts audio from video as MP3, WAV, M4A, OGG or FLAC, optionally trimmed.

**How it works**
- Modes: `mp4tomp3`, `movtomp3`, `mp4towav` and so on for every video input and audio output, plus `tomp3`, `towav`, `tom4a`, `toogg` and `toflac`.
- `--bitrate 128k|192k|256k|320k` for MP3, M4A and OGG (default `192k`). WAV and FLAC are lossless and ignore it.
- `--start` and `--end` accept `90`, `1:30` or `1:02:30`.
- Progress shows a percentage and time left.

**Tests**
- A video with no audio track fails with "has no audio".
- One MP4 gives an MP3 of the same length.
- A folder of videos all extract to MP3.
- Every audio format plays in common players, and WAV and FLAC are lossless.
- `--bitrate 320k` gives a bigger file than `128k`, and `100k` is rejected, listing the allowed values.
- `--bitrate` with `towav` warns that it's ignored.
- `--start 0:30 --end 2:15` gives a 1:45 clip.
- `--start` alone runs to the end, and `--end` alone starts from the beginning.
- `--start 90`, `--start 1:30` and `--start 0:01:30` give the same result.
- `--end` before `--start`, or `--start` past the end of the video, is rejected with the video's length.
- A damaged video fails with "looks damaged".
- A user pulls the audio from a recorded talk as an MP3 to share as a podcast.

**Done when:** Audio extracts to every listed format, and trimming is accurate to the second.

### 17. GIF (`togif`)

**What it does:** Turns an image or a short video clip into a GIF.

**How it works**
- Images use `sharp` (feature 6). Animated WebP stays animated, and other images become a still GIF.
- Video uses FFmpeg with a two-pass palette, so colours look good: it builds the best 256 colours for the clip first, then uses them.
- Video options: `--width` (default 480, keeping the shape), `--fps` (default 10, range 1–30), `--start` and `--end` (as in feature 16), `--speed 0.5–4` (default 1).
- Clips longer than 30 seconds need `--start`/`--end` or `--force`, because long GIFs are huge.
- Video GIFs loop forever.

**Tests**
- `togif` on a 0-byte file fails with "is empty".
- One PNG becomes a still GIF, and one animated WebP becomes an animated GIF with the same frame count.
- A five-second MP4 becomes an animated, looping GIF 480 pixels wide at 10 frames a second.
- A folder of short clips each becomes its own GIF.
- `--fps 1` and `--fps 30` work, and `0` and `31` are rejected.
- `--speed 2` halves the GIF's length, and `0.4` and `5` are rejected.
- `--start 0:02 --end 0:05` makes a three-second GIF.
- A 31-second clip without `--start`/`--end` or `--force` is refused with a tip, and a 30-second clip is accepted.
- A video GIF needs the FFmpeg add-on (feature 14), but an image GIF doesn't.
- The colours in a video GIF look right, without the banding of a plain conversion.
- `--fps` on an image input is rejected, because it only applies to video.
- A user turns a screen recording into a GIF for a README.

**Done when:** `togif` works on images and short videos, and video GIFs look good and loop.
