## Context

`scripts/update-readme.js` already generates the mode tables between markers and has a `--check` mode used by `test/readme.test.ts`. `src/help.ts` builds the "Common options" rows from `commonOptions` plus help-only options. `vhs` isn't installed on this computer.

## Goals / Non-Goals

**Goals:** a complete README that can't fall out of date; every example and link checked; a reproducible demo; a changelog and contributing guide.

**Non-Goals:** a documentation website; per-mode option tables in the README (`-m <mode> --help` covers them); publishing (feature 20).

## Decisions

- **Options section.** `src/help.ts` exports `commonOptionRows(): { name: string; explanation: string }[]`, built from `[...commonOptions, ...helpOptions]` with the existing `optionName` and `optionExplanation`; `mainHelp` keeps its padded rows from the same two functions. `update-readme.js` renders it between `<!-- options:start -->` and `<!-- options:end -->` as a `| Option | What it does |` table, with the name in backticks (`-o, --output <path>`). In the explanation cell, `<`, `>` and `|` are written as `&lt;`, `&gt;` and `\|`, so GitHub doesn't hide `<mode>`; the test undoes this before comparing. The test compares each help row (name trimmed) with the table. The existing marker-replacing code is reused for both sections, and `--check` covers both.
- **Demo image line.** `update-readme.js` writes `![konvertoj converting photos in a terminal](docs/demo.gif)` between `<!-- demo:start -->` and `<!-- demo:end -->` when `docs/demo.gif` exists next to the README being updated (looked up relative to the README's own folder, so tests can control it), and nothing otherwise, so the README never links to a missing file. This keeps `--check` deterministic for the files in the repository.
- **README rules.** `bash` code blocks hold only runnable mode examples. Command shapes, `--help`, `--list-modes` and `--install-video` go in `text` blocks or inline code. Links are inline `[text](target)` only, to pages that exist now; links to the npm package page, the GitHub repository and badges are left to feature 20. No two headings share a name.
- **README layout (hand-written outside the markers).** Title and one-line description; demo markers; "What it does" (local and private, formats, FFmpeg only for video); "Quick start" with a `bash` block: `npx konvertoj -m heictojpg holiday.heic`, `npx konvertoj -m compress hero.jpg`, `npx konvertoj -m topdf ./receipts -o receipts`; "Install" (`npm install -g konvertoj`, Node.js 22 or newer); "Usage" with the command shape, folders and globs, `-o`, never overwriting; "Modes" (generated); "Common options" (generated); "Video and audio" (the add-on, `--install-video`, cache folders per system, `KONVERTOJ_FFMPEG_PATH`, proxy settings, GPL credit); "Exit codes" (`0`, `1`, `2`, `130`); "Privacy" (nothing uploaded; the only network use is the add-on download you agree to); "Contributing" and "Changelog" links; "Licence" (MIT, and FFmpeg's licence for the add-on).
- **Examples test (`test/readme-examples.test.ts`).** Collects commands from inline code in table rows that starts with `konvertoj ` or `npx konvertoj ` and from lines in `bash` code blocks that start with either, plus every example of every registry mode (`--help` shows them all, so `crop --trim`, `rotate --auto`, `togif sticker.webp` and `compress --target-size` run too). A command containing a quote fails the test, and so does one with no `-m` or with a mode `findMode` doesn't know, so placeholders are caught. Each command is split on spaces. The test removes `-m <mode>` itself, then reads the other arguments with `acceptedOptions(mode)`, matching both `--name` and the short `-x` form: a value option skips its value; other non-option arguments are inputs. Each input is created in a fresh folder: a name with an extension becomes a real file of that format, 1000 × 1000 for images (so `crop --width 800 --height 800` and `colorpick --at 10,10` fit) (JPG, PNG, WebP, AVIF, GIF and TIFF with `writeImage` from `test/support/images.ts`; BMP and ICO by converting a PNG with konvertoj's own `pngtobmp` and `pngtoico`; HEIC from `test/fixtures/iphone.heic`; SVG as text; PDF with pdf-lib, three pages so `--page 3` works; videos with FFmpeg's `testsrc2` (64 × 36, 5 frames a second) and `sine` sources, three seconds longer than the command's `--start`, and at least three seconds, so `--start 1:30 --end 45:00` and `--start 0:02 --end 0:05` work, since `--end` past the end is capped at the video's length); a name without an extension becomes a folder with two files of the mode's first input format. Each command runs through `main` (as other tests do) with `{ environment: { ...process.env, KONVERTOJ_FFMPEG_PATH: <found FFmpeg> }, interactive: false }`, with `process.chdir` to its folder, and must return `0`. The test has a 15-minute timeout, since about 250 distinct commands run, about 42 of them with FFmpeg. A test checks every registry mode has at least one example among the commands collected from the README alone. Each distinct command runs once. Video modes are skipped when `findFfmpeg` finds nothing.
- **Links.** `scripts/check-links.js [README.md] [--offline]`: collects Markdown links and images (`[text](target)`), skips `mailto:`; relative targets must exist (relative to the README's folder, ignoring `#…`); code spans and fenced blocks are skipped; `#anchor` targets must match a heading slug the way GitHub makes them: formatting such as backticks removed, lower case, every character other than letters, digits, spaces, `-` and `_` removed, then each space turned into a hyphen without merging repeats (so `### Video & Audio` is `#video--audio`), with `-1`, `-2` added for repeated headings; without `--offline`, `http(s)` targets are fetched with `GET` and a 15-second timeout and must answer 2xx or 3xx (redirects followed). Prints each broken link and exits `1`. `test/readme.test.ts` runs it with `--offline` on the README, and on a temporary README with a broken file link and a broken heading link. CI's `check` job runs it online with `if: runner.os == 'Linux'`.
- **Demo.** `docs/demo.tape`: sets the output to `docs/demo.gif` and also `docs/demo.txt` (vhs's text output), a size, a theme, `Require node`, `Set Shell bash`, width, height, font size and theme. A hidden part (`Hide` … `Show`), while still in the repository folder, runs `alias konvertoj="node $PWD/dist/cli.js"` (so the path is absolute before changing folder), makes a `demo` folder in the system temp folder, copies `test/fixtures/iphone.heic` in as `holiday.heic` and changes into it, then clears the screen. It then types and runs `konvertoj -m heictojpg holiday.heic`, `konvertoj -m heictopng holiday.heic`, `konvertoj -m compress holiday.png -o small` (the fixture JPG is already optimised, so compressing it would show a skip) and `konvertoj --list-modes | head`, with `Sleep` between, and finally, hidden, removes the demo folder. `npm run demo` is `npm run build && vhs docs/demo.tape`; the tape types `konvertoj` (the alias), never `npx konvertoj`, which would look the package up on npm. The `demo` CI job on Ubuntu runs `actions/setup-node`, `npm ci`, `npm run build`, `charmbracelet/vhs-action@v2` with `path: docs/demo.tape`, then checks `docs/demo.gif` starts with `GIF8` and `docs/demo.txt` (which holds several screen snapshots) contains `1 converted, 0 failed` somewhere, and uploads the GIF with `actions/upload-artifact`. `docs/demo.txt` is ignored by git, and `.gitattributes` marks `*.gif` as binary.
- **Recording here.** `vhs` isn't installed on this computer, and installing and running downloaded recording tools isn't allowed in this environment, so `docs/demo.gif` isn't recorded in this feature. The tape, the script and the CI job are added; the GIF is recorded with `npm run demo` (or taken from the CI artifact) and committed, after which `npm run docs` adds it to the README. This is recorded in Decisions.md as a step still to do before release (feature 20), together with the fact that the demo job and online link check haven't run yet, since the work hasn't been pushed, and that relative README links only resolve on npmjs.com once `package.json` has a `repository` field (feature 20).
- **CHANGELOG.md** follows Keep a Changelog: an "Unreleased" section with "Added" items for features 1–19. **CONTRIBUTING.md**: requirements (Node.js 22+), `npm ci`, the four checks and `npm run docs`, the registry rule, adding a mode, Features.md build order, OpenSpec, coding rules link to CLAUDE.md, and the demo.
- `package.json` gets `"demo": "npm run build && vhs docs/demo.tape"`. The packed files are unchanged (README, LICENSE, dist).

## Risks / Trade-offs

- Online link checks can fail because a site is briefly down; it runs only in one CI job, and names the link.
- Running every example takes time (about 250 commands); inputs are small and the image ones run in a few seconds each batch.
